# 几何 source 语法（铺铜 / 禁布区 / 填充）

`easyeda pcb dump --include-copper` 里 `copper.poured[].fills[].source`、`copper.regions[].source`、`copper.fills[].source` 都是同一套紧凑数组语法。**不理解它就只能拿到 bbox，判断不了"这个焊盘下方有没有铜"。**

`scripts/eda_geom.py` 实现了下面全部规则，直接 import 用，别重写。

## 矩形

```
['R', x0, y0, w, h, rot, 0]
```

局部角点 `(0,0) (w,0) (w,-h) (0,-h)`，绕 `(x0,y0)` 逆时针旋转 `rot` 度。展开后等价于：

| rot | x 范围 | y 范围 |
|---|---|---|
| 0 | `[x0, x0+w]` | `[y0-h, y0]` |
| 90 | `[x0, x0+h]` | `[y0, y0+w]` |
| 180 | `[x0-w, x0]` | `[y0, y0+h]` |
| 270 | `[x0-h, x0]` | `[y0-w, y0]` |

**注意 y 是向下增长（EDA 坐标系），`h` 从 `y0` 往 -y 方向延伸。**

只按 `rot=0` 处理会出大错：本板 113 个矩形禁布区里有 rot=180 的，整体翻到反象限，凭空造出 57 条"禁布区内有铜"的假报。用 bbox 对照法自检：解析结果的 bbox 要和 CLI 自带的 `bbox` 字段逐条吻合（本板 115 个禁布区、18 个填充全部吻合才算解析正确）。

## 折线 + 圆弧

```
[x0, y0, x1, y1, ..., 'ARC', sweep, ex, ey, x2, y2, ..., 'ARC', ...]
```

`'ARC'` 后面跟的 **3 个数是：sweep 角度、终点 x、终点 y**。

**不是圆心。** 这是最容易搞错的地方——按"圆心"解读时，两个 180° 圆弧拼成的圆看起来自洽，但换成非 180° 就崩，而且算出的 bbox 会虚大好几倍。

- 180° 的双圆弧是最常见的圆（安装孔避让、圆形焊盘）：`[x,y,'ARC',180,x2,y,...]`，圆心在两点中点，`r = 距离/2`
- 一般角度：弦长 `L = 2r·sin(|θ|/2)`，圆心在弦的中垂线上；`sweep > 0` 取逆时针方向侧
- 终点本身就是路径顶点，解析时它是下一段的起点，不要重复插入

自检：把所有双 ARC 圆还原成圆心半径，检查每个顶点到圆心的距离偏差。本板 25 个圆的偏差全部 < 1mil 才算对。

## 多轮廓与 even-odd

`source` 外层数组的**每个元素是一个独立轮廓**，不是一条连续路径。

```
source = [ contourA, contourB, contourC, ... ]
```

铺铜是 complex polygon，按 **even-odd 规则**填充：一个点被奇数个轮廓包住才算在铜里。

所以不能把环拼成一条闭合路径——那样内部挖空（禁布区开的孔、散热焊盘的孔）会被填死，导致"晶振下方有铜"这类假报。正确做法是逐环 `point_in_contour`，计数取模 2。

## 不要报覆盖率百分比

环之间的并/异或关系在这个格式里无法确定。同一位置的三种解读能算出 3.3% / 53.7% / 97.5% 三个数。

**用二值判定代替**：拿实际焊盘坐标（`pcb dump` 的 `components[].pads[]` 有 `x`/`y`）逐个查 `point_in_complex`，得到"这个焊盘下方这层有没有铜"。这个结论在三种解读下完全一致，而且可复核。

## 坐标系与单位

- 单位 mil，y 轴向下
- 焊盘坐标是绝对坐标，铺铜 `source` 也是绝对坐标，直接比，不用换算
- 器件 `rotation` 与铺铜 `rot` 是两套东西，别混

## 已知降级

`pcb dump` 的 `partial[]` 会记录降级项。本板顶层 outline 报了 `outline polygon area is <50% of its bbox (likely an inner cutout)` → 被降级成 AABB。**降级项必须在报告里说**，不能装作没发生。
